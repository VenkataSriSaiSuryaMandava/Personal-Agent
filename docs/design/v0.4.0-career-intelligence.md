# Aegis AI v0.4.0 — Career Intelligence and LinkedIn

Status: Proposed implementation architecture.
Baseline: Published v0.3.0.
Current database schema: 6.

## Objectives

Build a local-first career assistant for job discovery,
resume management, matching, application preparation,
recruiter communication and interview workflows.

Preserve existing application functionality and private data.

## Architecture

Retain the existing Next.js and FastAPI modular monolith,
SQLite persistence and two-container private runtime.

Do not introduce additional infrastructure without evidence
of a functional requirement.

The public Guest demo remains independent and synthetic.
It cannot access private career data or connected accounts.

## Workspace design

Extend the existing Jobs workspace with:

- Discover
- Applications
- My Profile
- Documents
- Networking
- Interviews

Existing Jobs records remain the authoritative application
pipeline. Career-specific metadata extends these records.

Do not duplicate application status storage.

## Career data

Proposed storage domains:

- Career profile and preferences.
- Resume versions and private document metadata.
- Configured job sources.
- Normalized job listings.
- Explainable matching results.
- Extended application metadata.
- Application documents.
- Recruiter contacts.
- Integration account metadata.
- Enforceable action approvals.
- External action audit events.

Finalize schemas incrementally during implementation.

All migrations must preserve existing records and include
verified backup, rollback and recovery tests.

## Resume management

Support validated PDF, DOCX and text documents.

Initial proposed limits:
- 10 MB per upload.
- 20 retained resume versions.

Store documents in private runtime storage outside Git.
Use generated identifiers, never user-controlled paths.
Reject unsupported, encrypted or unsafe file structures.
Bound parsing resources and extracted content.

Document parsing must not execute macros, embedded code
or external document references.

Do not automatically delete old resume versions.
Protect downloaded documents and database backups.

## Job discovery

Initial source adapters:

- Greenhouse public Job Board API.
- Lever public Postings API.
- Ashby public Job Posting API.

Use explicitly configured company boards.
These sources do not provide comprehensive market coverage.

Provide manual LinkedIn, Indeed and company search links
where direct API access is unavailable.

Use fixed provider endpoints, validated identifiers,
bounded requests, timeouts, response-size limits,
deduplication and source provenance.

Do not fetch arbitrary user-controlled backend URLs.

Initial proposed operating limits:
- 100 configured job boards.
- Three concurrent source requests.
- 15-second request timeout.
- Six-hour cache freshness target.
- On-demand refresh.

Finalize cache storage limits and expiration behavior
during source adapter implementation.

No unauthorized scraping or automated applications.

## Matching and document preparation

Use deterministic local matching with explainable evidence.

Distinguish:
- Required qualifications.
- Preferred qualifications.
- Explicitly unmet requirements.
- Unknown information.

Do not infer unsupported sponsorship or eligibility status.
Do not fabricate experience, credentials or accomplishments.

Keep source documents and generated versions separate.
Track which resume version is associated with applications.

## AI privacy

Preserve the existing Gemini-only provider configuration.

Existing cloud policy permits reviewed public or synthetic
content, not personal or sensitive information.

Raw resumes, credentials and private LinkedIn content must
not be submitted to Gemini under the existing policy.

Local matching and document assembly remain available.
Broader cloud permissions require separate security approval.

Treat job listings, documents, posts and external responses
as untrusted data, never as agent instructions.

## LinkedIn integration

Connect only the authorized Owner account.

Use official OAuth authorization and permitted APIs.
Protect access tokens with encryption and separate key storage.
Bind authorization to the current Owner session.
Support expiration, revocation and disconnection.

Implement only capabilities granted to the application.

Basic profile access and approved post publishing are
candidate capabilities under supported permissions.

Feed access, private messaging, connection access and
direct message sending require additional verified access.

When an API capability is unavailable, offer local drafts
and manual LinkedIn navigation instead.

No session-cookie extraction, unauthorized browser automation
or scraping.

## External action approval

Introduce a real career-specific execution approval boundary.

Existing manual approval records do not grant execution.

Each executable approval binds:
- Owner and connected account.
- Action type.
- Exact recipient or destination.
- Exact content or payload digest.
- Creation and expiration timestamps.
- Single-use execution state.

Initial proposed approval validity: ten minutes.

Recheck authentication, integration scopes, emergency stop
and approval validity immediately before execution.

Prevent concurrent duplicate execution.
Do not blindly retry an action with an uncertain outcome.

Audit actual execution results without recording credentials
or unnecessary private content.

## Workspace coordination

Overview: career metrics and upcoming interviews.
AI Assistant: authorized career-specific capabilities.
Tasks: application and follow-up tasks.
Email: recruiter communication drafts.
Calendar: interview records.
Research: job and company research.
Coding: portfolio project references.
Browser: validated search and application links.
Memory: explicitly selected career context.
Approvals: career-related execution authorization.
Settings: integration scopes and permissions.

Defer unrelated external account integrations and
general autonomous execution.
